## 시스템 역할

카메라 영상은 Pi의 `vision.vision_pipeline`이 처리한다. YOLO는 영상에서 사람의 위치를 검출하는 모델이며, 검출 결과를 낙상·침입·방문자 판정에 사용한다. 택배는 사람이 떠난 뒤 배경과 달라진 물체를 비교해 판정한다.

```text
Picamera2 → YOLO / 감지기 → EventRecorder → EventEmitter → Render → Supabase
                    ↕
              AVShare (마이크 영상 요청·오디오 공유)
```

`EventEmitter`는 이벤트와 첨부를 로컬 전송 대기열에 저장하고 서버로 전송한다. 카메라 서비스는 최신 프레임을 보관해 하트비트와 현재 화면 캡처 요청도 처리한다. 백엔드는 Pi가 아니라 Render에서 실행된다.

## 주요 코드

| 파일 | 역할 |
|---|---|
| `vision/vision_pipeline.py` | 초기화, 프레임 처리, 모드 반영, 감지·녹화·전송 연결 |
| `vision/yolo_detector.py` | YOLO 검출과 대표 사람 선택 |
| `vision/fall_detector.py` | 중심 높이의 급하강 후 안정 상태로 낙상 후보 판정 |
| `vision/intrusion_detector.py` | 경비 상태 조회, 연속 사람 검출에 따른 침입 판정 |
| `vision/activity_tracker.py` | 등장·머무름·지나감·퇴장 상태 추적 |
| `vision/visitor_detector.py` | 지정 영역에서 머문 사람을 방문자로 판정 |
| `vision/delivery_detector.py` | 사람이 떠난 뒤 남은 물체 감지 |
| `vision/event_recorder.py` | 감지 전후 영상·썸네일 저장, 오디오 결합 |

| `edge/transport/event_mapper.py` | 감지 종류를 서버 이벤트로 변환 |

## 현재 코드 상태

- 카메라 설정: 640×480, 목표 5 FPS. 실제 추론 처리 속도는 Pi에서 확인 필요.
- 거실 모드: 경비 ON은 침입만, OFF는 낙상만 감지. 현관 모드: 경비와 무관하게 방문자·택배 감지. 음성·문열림은 이번 수정 대상에서 제외했다.
- 침입: 연속 3프레임 사람 검출, 같은 출현 중 중복 억제, 5프레임 미검출 후 재감지 준비. 장소·경비 상태는 `DetectionModeState`가 동일한 하트비트 응답으로 함께 적용한다. 별도 `GuardModeClient`는 main에서 사용하지 않는다. 갱신 주기는 기본 20초 + 요청 시간이며 최초 정상 응답 전에는 새 영상 감지 이벤트를 만들지 않는다. 통신 실패·불완전 응답은 마지막 상태를 유지한다.
- 낙상: 기본 4프레임 이력에서 중심 높이가 35px 초과 하강한 뒤 이동량 8px 이하인 상태가 2프레임 이어지면 판정한다. 자세·개인 식별을 보장하는 판정은 아니다.
- 일반 영상은 기본 감지 전후 각 3초를 녹화한다. 소리 이벤트의 영상 요청도 같은 녹화기를 사용한다.
- 2026-10-09 로컬 수정: 녹화 중 후속 이벤트를 종류별로 보관하고 저장된 클립으로 각각 전송한다. 침입·낙상은 경비 상태별로 분리하며 전환 전에 이미 감지한 이벤트는 보존한다. 같은 종류는 클립당 첫 감지만 유지한다. 기존 전송 쿨다운은 유지한다.
- 장소/경비 전환 시 낙상 이력·대상을 초기화하고 방문자·택배는 장소 전환 시에만 초기화한다. 하강 전 높이로 복귀한 낙상 후보를 취소하며 `history_frames` 설정을 판정에 반영한다.
- `FallPersonTracker`가 박스 겹침으로 낙상 대상 한 명을 이어서 선택하고 대상 변경·소실·모호한 겹침 시 이력을 초기화한다. 다인 교차·큰 이동에서 신원 보장 및 감지율은 확인 필요.
- 원본 영상·썸네일은 정상 큐 저장 또는 의도적인 쿨다운 제외 시 정리한다. 큐 저장 예외 시 원본을 보존하고 오류를 전달한다. 보존된 원본의 자동 재등록은 구현하지 않았다.
