안녕하세요, 여러분.

유리가 깨지는 소리나 경적처럼 언제 울릴지 모르는 소리를 감시하고 싶은 장면이 있습니다.그러나 일어날 수 있는 소리를 모두 사전에 등록하는 것은 현실적이지 않습니다.

자, 오늘은 YAMNet을 사용해서 '무슨 소리인지'를 맞히는 것이 아니라 '평소와 다른 소리가 들어갔는지'를 스트림 중에서 탐지할 수 있는지 검증하겠습니다.

먼저 결과를 쓰면 가장 좋았던 구성에서도 48건 중 22건을 검출했고 재현율은 45.8%였습니다.처리 속도에는 충분한 여유가 있었지만, 단순한 YAMNetembedding 거리만으로 미지의 돌발음을 안정적으로 감지한다는 가설은 지지되지 않았습니다.

YAMNet이란
YAMNet은 구글이 2019년 11월 21일 TensorFlow Models에 추가한 음성 분류 모델입니다.AudioSet에서 학습하고 있으며, 사람의 소리, 비, 자동차, 동물 등 521가지 음향 이벤트를 예측합니다.

내부에는 모바일용으로 계산을 가볍게 한 CNN인 MobileNet V1이 사용되고 있습니다.16 kHz mono 음성을 약 0.96초씩 읽고 다음 정보를 출력합니다.

scores(521차원) : 각 라벨다움
embedding(1,024차원) : 소리의 특징을 압축한 수치 표현
spectrogram(64 대역): 시간별 주파수 성분
이번에는 라벨 이름을 맞출 뿐만 아니라 embedding도 필요하기 때문에 TensorFlowHub의 Saved Model 버전을 사용했습니다.

라이선스는 다음과 같습니다.

YAMNetを含むTensorFlow Models: Apache License 2.0
TensorFlow: Apache License 2.0
ESC-50: Creative Commons Attribution-NonCommercial 3.0（CC BY-NC 3.0）
ESC-50은 비상용 조건을 포함합니다.모델과 데이터 세트는 별도 라이선스이므로 재배포나 제품 이용에서는 둘 다 확인해야 합니다.

이번에 검증할 내용
확인하고 싶은 것은, 정상적인 배경음에 갑자기 다른 소리를 섞었을 때, 라벨을 지정하지 않아도 변화를 검지할 수 있는지입니다.

주파수의 급변만을 보는 단순한 방법은 유효한가
YAMNet의 score와 embedding 중 어느 쪽이 변화를 포착하기 쉬운가
직전 음과의 거리와 정상음의 기억과의 거리에서는 어느 쪽이 유효한가
실시간보다 빠르게 순차적으로 처리할 수 있는가
완전한 코드와 결과는 kiarina/labs의 yamnet-streaming-novelty lab에서 공개하고 있습니다.

검증 환경의 재현
mise、uvFFmpeg, 첫 다운로드에 사용할 인터넷 연결이 필요합니다.모델과 데이터는 약 120MB, Python 환경은 약 1.3GB입니다.

git clone --depth 1 --filter=blob:none --sparse \
  https://github.com/kiarina/labs.git
cd labs
git sparse-checkout set .gitignore .mise/tasks Makefile mise.toml \
  2026/07/17/yamnet-streaming-novelty

첫회는 고정한 YAMNet와 ESC-50 revision으로부터 필요한 WAV 208 개를 취득합니다.YAMNetarchive는 SHA-256을 검증하고 결과를output/report.json에 저장합니다.

모델의 역할과 데이터 흐름
AI 모델은 YAMNet 하나뿐입니다.거기에 주파수 변화와 거리를 계산하는 작은 검출기를 조합했습니다.

16 kHz mono音声ストリーム
  ├─ 32 msごとの周波数変化 ──────────────> spectral flux
  └─ 0.975秒windowを0.48秒ごとにYAMNetへ入力
       ├─ 521 class scores
       │    ├─ 直前frameとの差 ──────────> score delta
       │    └─ 正常音の記憶との差 ───────> score kNN
       └─ 1,024次元embedding
            ├─ 直前frameとの差 ──────────> embedding delta
            └─ 正常音の記憶との差 ───────> embedding kNN
delta는 직전의 소리에서 얼마나 달라졌는지를 봅니다.kNN는 과거에 외운 정상음 중 가까운 5건과의 거리를 봅니다.거리에는 cosine distance를 사용했습니다.이것은 수치 벡터의 방향이 얼마나 다른지를 0에 가까울수록 비슷한 값으로 나타내는 방법입니다.

마지막으로 score delta와 embedding delta 중 어느쪽이 반응하면 alert로 한다temporal fusion도 평가했습니다.

평가 방법
정상음에는rain、sea_waves、wind、clock_tick을 사용했습니다.같은 5초의 배경음인 2.0~3.0초로,crying_baby、door_wood_knock、glass_breaking、siren、car_horn、fireworks중 하나를 삽입합니다.각 이벤트 8개, 총 48 스트림입니다.

이벤트의 음량은 배경에 대해 -10, -5, 0, +5dB의 4단계입니다.-10dB는 이벤트가 배경보다 상당히 작고, +5dB는 배경보다 큰 조건입니다.생성음은 평가 중에만 메모리에 두고, 파일로서 보존하고 있지 않습니다.

데이터는 녹음 단위로 분리되었습니다.

용 도	ESC-50 fold	clip수
정상음의 기억	1〜3	96
문턱값 결정	4	32
오보 평가	5	32
돌발 이벤트 평가	5	48 stream
임계치는 fold 4의 정상음에서 한번도 alert가 나오지 않는 값으로 했습니다.최종 평가인 fold 5를 보면서 조정하지 않았습니다.

검증 결과
어떤 score가 이상음을 알아보기 쉬웠는가
먼저 임계치를 고정하지 않고, 이상을 포함한 스트림이 정상 스트림보다 높은 score가 되는지를 AUROC에서 비교했습니다. AUROC는 1.0에 가까울수록 순위가 좋고, 0.5 전후면 거의 우연입니다.

detector	AUROC	-10 dB	-5 dB	0 dB	+5 dB
spectral flux	0.449	0.393	0.315	0.555	0.534
score delta	0.717	0.622	0.672	0.776	0.797
embedding delta	0.734	0.638	0.625	0.815	0.859
score kNN	0.661	0.484	0.698	0.789	0.672
embedding kNN	0.632	0.479	0.581	0.721	0.745
embedding delta가 0.734로 최고였어요.다만 score delta와의 차이는 0.018 뿐입니다.이번 80 평가 스트림만으로 embedding이 항상 우수하다고는 할 수 없습니다.

큰 경향으로서 정상음의 기억과 비교하는 kNN보다 직전음과 비교하는 delta가 더 좋은 결과였습니다.이번처럼 짧은 돌발음에서는 '정상인가 아닌가'보다 '지금 갑자기 바뀌었는가'가 더 단서가 되었습니다.

엄격한 문턱값으로 alert를 내다
detector	precision	recall	F1	오alert/시	지연 중앙값
spectral flux	0.000	0.0%	0.000	0.0	—
score delta	0.810	35.4%	0.493	22.5	0.415초
embedding delta	0.765	27.1%	0.400	22.5	0.415초
score kNN	1.000	6.2%	0.118	0.0	0.895초
embedding kNN	0.800	16.7%	0.276	0.0	0.895초
score delta + embedding delta	0.786	45.8%	0.579	22.5	0.415초
precision은 "낸 alert 중 옳았던 비율", recall은 "48건의 이벤트 중 찾은 비율"입니다.가장 좋은 temporal fusion은 22건을 검출하고 26건을 놓쳤습니다.

오류는 정상음 160초 중 1건 뿐이었어요.22.5건/때는 그 1건을 1시간으로 환산한 값이므로, 실제 운용의 오보율로서는 불안정합니다.적어도 몇 시간 동안의 연속음으로 다시 측정해야 합니다.

음량별로는 다음 결과였습니다.

이벤트 음량	검출수	recall	지연 중앙값
-10 dB	4/12	33.3%	1.855초
-5 dB	3/12	25.0%	0.415초
0 dB	7/12	58.3%	0.415초
+5 dB	8/12	66.7%	0.415초
행사별로는 유리가 깨지는 소리가 6/8, 불꽃이 5/8, 경적이 4/8이었습니다.아기의 울음소리와 사이렌은 각 2/8입니다.짧고 날카로운 변화는 비교적 찾기 쉽고, 배경에 익숙해지는 소리나 1초의 말풍선만으로는 특징이 약한 소리는 어려운 결과였습니다.

잘 되지 않았던 방법
단순한 spectral flux는 문턱값을 늦추면 recall 29.2%에 대해 오alert가 967.5건/시가 되었습니다.자연적인 비나 파도에도 주파수 변화가 많아 돌발 사태만 구별할 수 없었습니다.

spectral flux와 embedding kNN의 융합도 엄격한 임계값에서는 embedding kNN 단체와 동일한 recall 16.7%였습니다.풀면 recall 45.8%까지 올라갔지만, 오alert는 607.5건/시입니다.검출기를 추가하는 것만으로는 개선이 되지 않았습니다.

또 novelty score가 비싸더라도 YAMNet의 top label이 옳다고는 할 수 없습니다.유리음 8건 중Glasstop은 3건이고 음량이 작은 조건에서는 배경의Water、Rain、Vehicle등이 남았습니다.'변화했다'와 '무슨 소리냐'는 다른 문제입니다.

처리 속도
Mac Studio(Apple M4 Max)에서 1,040초분을 순차 window로서 처리했습니다.

feature extraction elapsed: 6.262秒
real-time factor:           0.0060x
기사 집필 시 동일한 명령어로 재실행하면 6.921초, real-time factor는 0.0067x였습니다.검출 수, AUROC, 임계값, 지연은 원래 측정과 일치합니다.YAMNet 추론과 spectral flux를 포함해 두 번 모두 음성 길이보다 약 150배 이상 빠르게 처리할 수 있었습니다.계산량에는 충분한 여유가 있습니다.

한편, YAMNet은 약 0.96초의 소리를 정리해 읽기 때문에, 최단의 관측 지연은 0.415초였습니다.속도가 빨라도 window 설계에 따른 대기 시간은 남습니다.

결과를 간단히 읽다
전문적인 수치를 정리하면 다음 세 가지입니다.

움직이는 속도에는 문제가 없었다

1,040초의 소리를 2번의 측정으로 6.262~6.921초에 처리할 수 있었습니다.실시간 감시에 필요한 계산 속도는 충족합니다.

우리는 미지의 소리를 찾는 정확도가 부족했다

최소 48건 중 22건이었습니다.특히 작은 소리는 배경에 묻힙니다.이대로 안전 감시 등에 사용할 수 있는 정밀도가 아닙니다.

'정상음에서 먼가'보다 '직전부터 바뀌었는가'가 유효했다

embedding을 정상음 기억과 비교하는 방법보다 직전 frame과 차이를 보는 방법이 더 좋은 결과였습니다.짧은 돌발음에는 국소적인 변화가 중요했어요.

본 검증은 5초의 합성 스트림 48건, 정상음 160초, ESC-50의 한정한 10 카테고리, 1대의 Mac에 한정됩니다.실제 마이크의 연속음, 몇 시간의 오보율, 녹음 기기의 차이, 동시에 여러 소리가 울리는 환경은 미검증입니다.

검증 후 소감
YAMNet은 충분히 가볍고, score와 embedding을 모두 꺼낼 수 있기 때문에, 소리의 변화를 시험하는 토대로서는 다루기 쉬운 모델이었습니다.다만 embedding에는 소리의 특징이 들어가 있어도 그 단순한 거리가 그대로 '이상함'이 되는 것은 아니었습니다.

이번 결과에서는 정상음을 대량으로 외우게 하는 방법보다 직전부터의 변화를 보는 것이 솔직하게 효과가 있습니다.유리나 불꽃과 같은 급한 소리를 후보로서 주워, 그 후에 YAMNet의 라벨이나 다른 판정을 조합하는 경량인 1차 검지에도 사용할 수 있을 것 같습니다.
