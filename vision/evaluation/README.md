# 영상 이벤트 정확도 평가

작성: 2026-10-13. 참고: `SH_README/hometalk_테스트셋_평가계획.md`.
이번 작업은 `vision/` 안에만 추가했다. 운영 감지기·임계값·전송 코드는 변경하지 않았다.

## 평가 범위

`replay.py`는 로컬 영상 → 기존 YOLO → 기존 낙상/사람 추적/방문자/택배/침입 감지기를 실행한다.
Picamera2, 환경변수 파일, 카메라, 백엔드를 사용하지 않는다. 새 의존성은 없으며 재생에는 기존 vision 의존성이 필요하다.
모델 파일은 로컬에 있어야 한다. 모델 다운로드나 설치는 이 도구에서 수행하지 않는다.
파이프라인 설정 상수는 AST(파이썬 소스의 구문 구조)로 읽어 카메라 모듈을 실행하지 않고 재사용한다.
감지기 기본값은 원래 클래스를 따른다. 호출 순서·모드 분기는 현재 파이프라인에 맞춘 독립 어댑터이므로,
운영 파이프라인 분기가 바뀌면 어댑터도 검토해야 한다. 결과에 설정·소스·모델·라벨 SHA256을 남긴다.

**이 결과는 오프라인 감지 단계 정확도다.** 녹화 중 병합, 전송 쿨다운, 네트워크, DB 저장,
소리 융합, 실제 Pi의 프레임 드롭/동기 녹화 공백은 재현하지 않는다.
영상 시각을 감지기에 전달하므로 재생 지연은 영상상 지연이고 서버 도착 지연이 아니다.
처리 벽시계 시간도 기록하지만 카메라 서비스의 실제 FPS로 해석하지 않는다.
고정 프레임률(CFR) 영상만 사용한다. 가변 프레임률이나 프레임 누락이 있는 원본은 별도 타임스탬프 기반 평가가 필요하다.

## 촬영 시나리오

아래 수는 최종 test 목표이며 튜닝용 dev는 별도 촬영한다. 발표용 최소 규모로서 일반화를 보장하지 않는다.

| 종류 | 양성 30개 구성 | 음성 30개 구성 |
|---|---|---|
| 방문자 | 정면/좌/우 접근 후 ROI 안 3~5초 체류 각 10 | 짧은 통과 10, ROI 밖 체류 10, 그림자·반려동물 10 |
| 택배 | 큰 고대비 상자/작은 상자/바닥과 비슷한 상자 두고 퇴장 각 10 | 기존 물건 회수 10, 들고 퇴장 10, 조명·문·카메라 흔들림 10 |
| 낙상 | 앞/옆/뒤 방향 안전한 모의 넘어짐 후 낮은 자세 유지 각 10 | 빠른 착석 8, 천천히 눕기 8, 줍기 7, 바닥 운동 7 |
| 침입 | 거실 경비 ON에서 정면/측면 진입·퇴장 후 재진입 각 10 | 경비 ON 무인 변화 10, OFF 사람 진입 10, 현관 사람 진입 10 |

- 실제 Pi 카메라·설치 위치에서 약 20~30초 촬영. 시작 5초 빈 화면, 사건 뒤 최소 10초 관찰.
  택배는 사람 퇴장 후 확인 시간이 필요하므로 충분히 기다린다. 음성 클립도 길이를 맞춘다.
- 낙상은 안전 매트와 보조자 아래 가능한 통제된 모의 동작만 사용한다. 위험한 실연은 하지 않는다.
  모의 동작 결과로 실제 노인 낙상 일반화를 주장하지 않는다.
- 각 종류에서 낮/밤 각 15개, 근/중/원 각 10개를 교차 배치한다. 거리 실제 m, 가림 여부,
  촬영일·카메라 각도·ROI 좌표·노출·참여자 가명은 별도 로컬 촬영 기록에 남긴다.
- 가족도 ROI에 오래 있으면 현재 정책상 방문자다. 신원으로 양성/음성을 나누지 않는다.
  현재 ROI가 전체 화면이므로 ROI 밖 체류 실험은 dev에서 설치 ROI 확정 후 진행한다.
- 택배 회수·정지 그림자는 알려진 오탐 후보. 낙상은 시간·크기 비율 기반이며 과거 문서의 픽셀 기준은 현재와 다르다.
- 최소 3개 세션: dev 1~2, test 3 이상. 같은 촬영의 잘라낸 클립은 같은 session에 묶는다.
  파일명만 다른 복제본/동일 출연자의 반복 촬영 누수는 사람이 점검한다. 가능하면 test 날짜·참여자도 분리한다.
- dev에서만 임계값/ROI 조정 → 설정 동결 → test 평가. test를 보고 수정하면 새로운 test 세션을 확보한다.

### 장시간·복합 평가

현관, 거실 경비 ON, 거실 경비 OFF 각각 낮/밤을 포함한 1~2시간 무사건 영상을 권장한다.
방문자 배경 영상에는 오래 체류하는 사람처럼 정책상 양성인 장면을 넣지 않는다.
거실 경비 OFF의 일반 생활은 낙상 음성 평가로 사용할 수 있다.
무사건 여부는 **평가할 이벤트 종류 기준**으로 수동 확인한다.

다인 장면, 녹화 중 두 번째 사건, 장소/경비 전환, 연속 사건의 쿨다운 누락은 Pi 실기 별도 평가다.
이 재생기는 한 클립 안의 모드 전환을 지원하지 않는다. 실기에서는 사건 시작·감지·큐 저장·서버 저장
시각과 성공 여부를 각각 기록하고 UUID/첨부 재생을 확인한다. 서버 확인 작업은 이번 구현에서 수행하지 않았다.
YOLO 박스 AP50은 별도 수동 박스 라벨이 필요하여 이번 도구 범위에 포함하지 않았다.

## 라벨 작성

`labels.example.csv`를 복사해 `data/labels.csv`를 만들고 실제 촬영값으로 채운다. 예시는 실행 가능한 실제 데이터가 아니다.
`file`은 **라벨 CSV 파일 기준** 상대 경로 또는 절대 경로다. 예시를 data 안으로 복사하면 file 경로도 맞춘다.

| 필드 | 의미 |
|---|---|
| clip_id, file | 고유 평가 ID와 영상 파일 |
| session, split | 촬영 세션과 dev/test. 같은 세션/파일이 두 split에 있으면 오류 |
| scenario, lighting, distance | 시나리오·조명·거리 그룹; clips.csv에서 조건별 분석 가능 |
| category | visitor_detected, delivery_suspect, fall_suspect, intrusion_suspect |
| label, kind | 사건 있음 1/없음 0; clip 또는 background(항상 0) |
| start_s, end_s | 양성: 사건 시작부터 허용 감지 마감까지. 음성: 0~영상 전체 길이 |
| duration_s | 실제 영상 전체 길이(초) |
| mode, armed | entrance/living, 경비 0/1. 양성 라벨은 활성 정책과 일치해야 함 |

허용 구간은 **추론 결과를 보기 전에** 고정한다. 권장 초안: 방문자 ROI 진입~+6초,
택배 최종 물체를 놓은 시각~사람 퇴장 후 8초, 낙상 하강 시작~+4초, 침입 진입~+2초.
이 마감은 제품 요구사항 초안이며 확정한 값을 모든 dev/test 라벨에 일관되게 적용한다.
한 클립에는 해당 종류의 사건을 최대 하나만 넣는다. 같은 영상의 여러 종류를 채점하려면
종류별 별도 clip_id 행으로 등록한다(같은 session/split 유지). 재생은 행마다 초기화된다.
배경 영상도 종류별 행으로 등록하며 시간당 오경보는 종류별로만 계산해 중복 노출 시간을 합산하지 않는다.

## 실행 (저장소 루트, 기존 Pi 가상환경)

```sh
python -m unittest vision.evaluation.test_evaluation
python -m vision.evaluation.replay vision/evaluation/data/labels.csv --split dev --output vision/evaluation/output/dev
python -m vision.evaluation.replay vision/evaluation/data/labels.csv --split test --output vision/evaluation/output/test
```

기존 출력 경로를 다시 쓰면 덮어쓴다. 실험별 다른 output 경로를 사용한다.
`predictions.json`에 모든 종류의 원시 감지 시각, `report.json`에 요약/재현 정보,
`clips.csv`에 클립별 결과·조건·중복·지연을 저장한다.
집계만 재실행하려면 영상 의존성 없이 다음 명령을 사용한다.

```sh
python -m vision.evaluation.evaluate vision/evaluation/data/labels.csv --split dev --predictions vision/evaluation/output/dev/predictions.json --output vision/evaluation/output/rescore
```

예측 JSON 형식: `{"metadata":{"stage":"offline_raw_detection"},"predictions":{"clip_id":[{"category":"fall_suspect","time_s":6.2}]}}`.
무감지는 반드시 `"clip_id": []`로 명시한다. 선택 split과 예측 ID가 정확히 일치해야 한다.
다른 split 예측이나 누락된 실행을 미감지로 점수화하지 않는다.

## 지표 해석

- TP/FP/TN/FN: 해당 종류가 클립 전체에서 한 번이라도 감지되면 예측 양성.
  다른 종류 출력은 해당 행의 FP로 세지 않는다. 모든 종류 평가에는 각 종류 라벨이 필요하다.
- Precision(감지한 클립 중 실제 사건 비율), Recall(실제 사건 클립 중 감지 비율), F1,
  Accuracy, MCC(양·음성 불균형을 함께 고려한 상관 지표)를 계산한다.
- 클립 TP여도 사건 전에만 감지했을 수 있다. `timely_recall`은 정답 구간 안 감지를 별도로 요구한다.
  시간 기준 제품 성공률을 보고할 때 clip Recall만 제시하지 말고 함께 보고한다.
- `latency_median_s`는 정답 구간 안 첫 감지 지연. 미탐은 지연 표본에 포함하지 않으며 `latency_n`을 함께 보고한다.
- `extra_clip_events`는 첫 감지 이후 같은 종류 추가 감지 횟수다. 클립 혼동행렬에서 FP를 추가하지 않는다.
- `background`는 혼동행렬에서 제외한다. 원시 감지 횟수/무사건 시간 = `raw_false_events_per_hour`.
  쿨다운 적용 전이므로 실제 사용자 알림 FA/h와 구분한다.
- Precision/Recall에 Wilson 95% 신뢰구간을 병기한다. 같은 세션의 상관성까지 보정하지는 않는다.
  F1/MCC의 신뢰구간은 구현하지 않았다. 분모가 0이면 JSON null(계산 불가).
- macro-F1은 정의 가능한 종류만 평균하고 포함 종류 수를 표시한다. 서로 다른 종류 구성의 실험을 그대로 비교하지 않는다.
  규칙 출력에 연속 점수가 없으므로 ROC-AUC는 계산하지 않는다.

오류 검토는 clips.csv 각 행에 대해 별도 로컬 기록으로 ① 사람 검출 실패 ② 규칙 문제
③ 추적 대상 변경 ④ 모드/촬영/라벨 오류를 사람이 분류한다. 자동 원인 판정은 하지 않는다.

## 보관 및 검증 기록

`vision/evaluation/data/`, `output/`는 이 폴더의 `.gitignore`로 제외했다.
얼굴·원본 영상·실제 라벨·예측 결과는 그 안에 보관하며 다른 경로에 두면 자동 제외되지 않는다.
실제 영상 데이터가 없으므로 현재 제품 정확도 수치는 아직 없다.

  모의 디코더 검증을 실제 영상 재생 성공으로 간주하지 않는다. 백엔드 변경이 없어 Jest는 실행하지 않았다.

인수인계: 다음 작업은 Pi 촬영 → 실제 라벨 작성 → dev 재생 → 오류 영상 검토 → 설정 동결 → 새로운 test 평가다.
결정 이유: 감지기 원형과 운영 정책을 보존하면서 로컬에서 재현 가능한 감지 단계 기준선을 먼저 확보한다.
사용자 요청에 따라 TH_README/SH_README/루트 설정에는 기록이나 수정을 하지 않았다.
